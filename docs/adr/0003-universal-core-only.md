# 通用核心配置：仓库只声明每台开发机都需要的

用户拥有多台开发机（模式相近：Windows + WSL，Python/TS/Go），本仓库将应用到全部机器。判据：只有「每台开发机都需要」的内容才进核心声明（编辑器、终端、shell、语言管理器、git、CLI 工具、系统偏好）；机器个性化的工具（本机的 JetBrains 套件、Typora、GitHub Desktop）不进仓库，由各机手动安装维护，且受「移除清单之外不碰」原则保护。同一判据的推论：**git 身份因机而异，属机器数据**——仓库中的 gitconfig 模板不含 [user] 段，通过 `include.path = ~/.gitidentity` 引用每台机器本地的身份文件（bootstrap 首次生成占位，不入仓库）。拒绝的替代：按机器拆 profile（目前各机差异仅个性工具，不值得）；仓库内置可选模块/override 机制（为假想的共享需求做设计，YAGNI，真出现再引入）。

**修订标注（2026-11-21，v1-program 工单02）**：判据补第二轴——**开发环境相关性**。「每台开发机都需要」是必要非充分条件，候选还须面向开发环境；通用消费软件（浏览器/网盘/媒体/聊天类）即使人人用也出局，归机器自留地。判例：Chrome 除名（Edge 预装同内核等价；chrome 域随批退役，存量机不卸载转自留地——ADR-0007 收敛-only 语义不变）；Everything / PowerToys 审视后保留（系统级开发提效，无预装等价物）。工单40 的 chrome 独立域（CI DO 闪失败隔离设计）随除名成为史档。

**修订标注二（2026-11-21，v1-program 工单03——VSCode 全让位）**：同轴再判例——VSCode 扩展/设置/键位属**账号态**（跟人走的个人配置），让位 VSCode 原生设置同步，WDC 只装本体。原「要求关闭 VSCode 设置同步」（仓库是唯一主人）撤销——那等于替账号做主、与原生机制打架，正是「弄坏用户已有环境」批评的具体形态；对照上游 WindowsDeveloperConfig 同款边界（只装本体、不装扩展、不碰其配置文件）。落地：dotfiles-map 7→5（VSCode settings/keybindings 出列）、扩展清单与安装脚本除名、README 首跑配合事项由「关同步」反转为「登录开同步」、`wdc exit` 不再卸扩展（账号数据，数据面不动原则延伸）。
