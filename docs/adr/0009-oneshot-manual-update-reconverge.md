# 定位改一次性配置——更新与回归皆为显式手动行为

2026-11-21 主人定夺（对照 microsoft/WindowsDeveloperConfig 当日逐项对拍的结论：其「一次性 opinionated 安装器 + 每项设置文档化 undo + CI 矩阵」的稳，对照出本仓持续收敛姿态的暴露面）。本仓自初始构建起的默认叙事是持续收敛：`wdc sync` 框架为「日常一键同步」、漂移检测/triage 构成日常纪律、多机以「随时全绿一致」为目标态。真机实录（坑1–18）表明暴露面最大处恰是持续收敛在活机器上的反复触碰（升级竞态坑14、漂移处置打地鼠、异质环境适配），而首次全新机器的一次性收敛反而是被打熟的路；主人自述痛点即「不同环境适应性差、易碰坏已有环境」。

## 决策

- **默认姿态改一次性配置**：bootstrap 跑一次把机器带到声明状态，之后 WDC 休眠——无定时收敛、无漂移纠察，机器日常归用户，**漂移是合法状态而非异常**。
- **更新与回归皆为显式手动行为**：更新=拉新声明后重跑（`wdc sync` / bootstrap）；回归=漂移后显式重跑、把机器拉回**当前**声明状态（主人钉死方向：拉回声明，非 uninstall/回滚——退出路径另议）。漂移积累越久单次回归覆盖面越大，`wdc plan` 干跑预演升格为回归前推荐步骤。
- **命令定性调整、机制原样**：`wdc sync` 从「日常一键同步」降为「手动更新/回归入口」（名字与行为不变，只改框架叙事）；`wdc` 快照 / verify / triage / audit 定性为按需诊断工具。bootstrap 幂等、渲染拷贝、收敛账本快速路径、运行锁、续跑任务、ADR-0007 移除清单收敛-only 语义全部不动——**本 ADR 零行为变更**。
- **多机一致性承诺收缩**：机器各漂各的，一致性只在各机手动更新/回归时点对齐，「随时全绿」不再是对等的目标态；机器对等的工单/决策流转语义不变（GLOSSARY「机器对等」）。
- **首次跑在已有环境的机器上仍是最危险一步**（一次性模式下成为产品的全部暴露面）：ADR-0007「清单外一概不碰」是该场景的守门员，语义加固不变。

## 取舍

拒绝的替代：**改成微软式「装完即走」的一次性产品**（丢 verify/triage/sync 与多机对等仓流——本仓保留按需重放能力，定位是「一次性配置 + 可显式更新/回归」，与无状态安装器划界）；**删除漂移检测/triage/sync 机制**（它们正是手动更新/回归的工具箱，删了回归路径裸奔）；**sync 改名**（update/reconverge 之类——改名成本与肌肉记忆不抵收益，语义降格已达目的）。LDC 姊妹仓定位不随本 ADR 联动（双边最优化，主人另行定夺）。
