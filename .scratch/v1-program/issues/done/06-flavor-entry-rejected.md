# 06 风味入口（WDC_FLAVOR=full/tools）——评估后撤销

Status: wontfix
Type: task

## 经过

主人 2026-11-22 提出外部用户诉求（一次性操作、「用后即删」、不想被深度接管系统配置）→ 曾定夺「风味入口进 1.0.0」→ 设计过程（边界确认「纯工具盘」）后主人终局反转：**tools 盘没啥意义，撤销**。

## 撤销理由（主人 2026-11-22 终局定夺）

纯工具盘（cli-tools + editors + 语言）≈ 一份 winget 清单脚本——WDC 的核心价值（终端体验/dotfiles 渲染/系统调优/退出闭环）全不在 tools 盘里；为小众场景引入风味机制（账本记风味、verify/exit 按风味裁剪、CI 风味腿、文档面）复杂度买不回价值。外部用户的真实诉求由既有机制覆盖：

- **用后即删**：ADR-0015 渲染拷贝后运行时不依赖仓库 + shell 配置全守卫（仓库缺席优雅降级）+ `wdc exit -KeepTools`（T1）+ 手删 clone——README「一次性使用」节文档化（本批落地）；
- **不想被接管**：fork 裁剪既有路径（README「使用与改造」改造清单）+ 完整退出（`wdc exit`，ADR-0010）。

## 教训

风味是给「中间态用户」的设计；WDC 的用户面两端（作者全席 / 一次性外部用户）都已有更简单的解。若未来真出现「要工具但不要终端体验」的持续需求，重估时先问它为什么不是 winget 清单。
